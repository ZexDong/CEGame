# Deep Relay Public Visual Specification

## 1. Visual goal

Present a readable, complete underground relay facility with a maintenance theme.
Area identity, interactions, and hazard states must be clear; exact layout
replication is not required.

Suggested visual language:

- Structure: dark gray metal, concrete, low-saturation structural parts.
- Power: amber and warm-white indicators.
- Coolant: cyan/blue pipes, pressure gauges, and fluid symbols.
- Authorization: purple/magenta data lights.
- Safe/completed: green.
- Error/danger: red.
- Relay core: white body with cyan energy bands, distinct from ordinary parts.

Color must not be the only signal. Pair key states with text, icons, materials,
or observable component changes.

## 2. Area and object readability

Show directions to all three services from spawn. Each service has a large name
sign and consistent color. Interactable parts have real ProximityPrompts and
look distinct from decoration.
Outputs, assembly slots, doors, checkpoint shelf, hazard strip, relay socket,
and all three stabilization nodes must be recognizable.
Activation, locking, rejection, carrying, equalization, checkpoint activation,
death recovery, and completion have visible feedback.
Exclude placeholder text, debug blocks, developer coordinates, test buttons,
and floating/unassembled assets.

## 3. HUD

Show objective, three service statuses, carried item, relevant pressure/airlock
state, current checkpoint, run timer, and latest feedback.
Keep text inside the viewport without overlaps. Completion has a separate panel,
final time, and R restart prompt.

## 4. Representative states

Visual review selects 3-5 states such as the initial facility, assembly after
three modules, carrying the core through the airlock/hazard, and completion.
Equivalent layouts are allowed while preserving primary content, state colors,
hierarchy, and finish.
