# Private semantic setup mapping

The scorer and player never import Gold code. Normal-input cases require only the
public observation contract. Complex isolated preconditions use the versioned
engine state-fixture transport in an assessment-only project copy.

GoldMapping.cpp is one explicitly fingerprinted mapping for the reference source.
InputMapping.cpp is a host probe for the untouched input. Neither is a requirement
on candidates. A candidate with different classes, modules, collections or object
layout needs its own evaluator-owned reviewed mapping and identity receipt. Never
select GoldMapping based on a module name, filename or a failed candidate build.
An absent or incorrect mapping is an authoring blocker, not a candidate zero.

All apply requests start in a new process. The transport requires an assessment
identity, random authorization nonce and single-use sequence. Setup is committed
paused, before any tested action, then corroborated with native reads, public
snapshots and a client capture. Normal P input releases the setup. Purchase,
upgrade, sale, damage, reward, spawn, wave-clear, defeat and restart results are
never injected. Positive-health entities and pending timers are prerequisites.
No state setter, private source or nonce enters input/ or delivered gold/project/.

For future candidates: inspect their source only to map public concepts into the
external adapter; retain a field whitelist and a patch receipt. Source inspection
cannot establish gameplay passes. Run the same semantic setups, real inputs and
assertions after mapping. Do not change the public GDD, expected values or weights.
# Authorized assessment assistance

The task owner permits candidate-specific assessment helpers, including extra
funds or protected health, to establish otherwise expensive prerequisites.
Review each Gold/scaffold mapping separately and bind it to the exact source
identity. Assistance must be inactive for the rule it could mask: use normal
funds for economy tests and normal damage/health for combat or defeat tests.
Setup may not invoke the action under test or write its expected result.
Keep all helpers in private assessment copies; a mapping failure is an evaluator
blocker, never a candidate gameplay failure.
