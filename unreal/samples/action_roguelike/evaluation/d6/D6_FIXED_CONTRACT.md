# D6 canonical visual protocol

The fixed prompt is the bundled English text in `d6/FIXED_VLM_PROMPT.txt`. Only its state-label placeholder is replaced. Each call contains exactly one original-derived reference image followed by one candidate image. The seven-line response contains five half-point components, their sum, and a rationale of at most two sentences. JSON, markdown fences, extra lines, inconsistent sums, missing components, and reordered criteria invalidate the run.

The manifest fixes 3–5 equal-weight states. Three complete ordered rounds use one model ID, version, and actual parameter object. Every request and provider response carries this identity; every request binds the exact substituted prompt and ordered image hashes. Parameters are retained, not replaced by an unverifiable hash. Request IDs must be unique. Raw request and response objects are saved separately and hashed using canonical JSON with ordinal sorted keys. State sums and round means retain full precision; rounding is only for display and final one-decimal reporting.

`Invoke-ActionRoguelikeD6Aggregation.ps1 -ResponsesPath` accepts an evaluator-owned evidence bundle (schema `3.0.0`). It contains `game_id`, candidate ID/identity hash, fixed prompt hash, `model` (`id`, `version`, `parameters`), `capture_health`, ordered `states`, and three ordered `rounds`. Each round has `round` and `states`; each state has `state_id`, `request`, and `response`. A request has `request_id`, `model`, `prompt`, and ordered `images` (`role`, `sha256`); the response has matching `request_id`/`model` and raw seven-line `text`.

`capture_health` requires `status=healthy`, an independently healthy 1280×720 control image and SHA-256, and a receipt path/hash. The health receipt must echo `status=healthy`, the candidate identity hash, and the control image hash. Each state records `state_id`, measured `status`, `attribution`, and a receipt path/hash; that receipt must echo the state ID, candidate identity, status, and attribution. All paths are explicit, relative to the evidence bundle; path escapes and reparse points are rejected. Candidate captures are exactly `<state_id>.png` in the supplied capture directory. A healthy frame requires attribution `none`. A missing or black/blank frame requires positive healthy capture evidence and attribution `candidate`, then receives five zeros in every round (request/response are null). Damaged capture files, incorrect image dimensions, contradictory receipts, and unhealthy capture controls are infrastructure faults, not candidate deductions.

References must be ready, hash-valid, healthy original-derived images with a source identity and capture receipt path/hash in each state's `provenance`. Existing `gold_authoring_run` images remain diagnostic evidence with their true provenance and cannot be scored or relabelled. The checked-in references are captured from the semantically preserved `baseline_ue5_6` derived from the preserved original source.

The aggregator copies the evidence bundle, explicitly bound receipts/control images, candidate captures, and raw request/response records into its output. It replays those copied bytes before completing. The canonical scorer independently replays the same evidence and rejects any identity, provenance, health, parser, component, source, aggregate, or raw-artifact mismatch. `schemas/d6-run.schema.json` describes the output envelope; semantic checks are in `ActionRoguelikeD6Protocol.ps1`.

All reference, capture-infrastructure, VLM, parser, identity, and protocol faults produce `run_invalid` with evaluator attribution and no score. Tests use newly generated synthetic images in disposable evaluator copies; they never modify the repository's reference manifest or relabel its Gold images. This package remains diagnostic and does not perform a formal freeze.
